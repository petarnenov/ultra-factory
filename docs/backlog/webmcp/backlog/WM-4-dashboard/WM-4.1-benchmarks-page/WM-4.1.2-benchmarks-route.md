## Blueprint

```tsx
// routes/_shell.benchmarks.tsx
export const Route = createFileRoute("/_shell/benchmarks")({ component: BenchmarksView });

// components/benchmarks/BenchmarksView.tsx
// state: page filter ("all"|"board"|"settings"|"chat"), driver toggles (Set<Driver>)
// data: const { records, summary, error } = useBenchmarkData();   // benchmarks/load.ts: static import + validateRecord on each; memoised
// layout (top → bottom, single column, max-w like Settings pane):
//  1. header: title t("benchmarks.title"), commit + timestamp + env line from records[0]
//  2. <SummaryTable rows={filtered}/>  scenario × driver: median ms (min–max) · pass n/N · ×PW
//  3. <Tabs> "Totals" | "JEV breakdown" | "Repeats" | "Pass rate", each tab = <Card> with chart + <TableTwin>
//  4. empty state when data missing/invalid: t("benchmarks.empty")
```

Charts (all `ChartContainer` from WM-4.1.1):

| Tab | Chart | Data |
|---|---|---|
| Totals | grouped `BarChart`, x = scenario, bars = driver medians, `ErrorBar` min–max; `ReferenceLine` = overhead median per step × median step count | `summary` |
| JEV breakdown | stacked `BarChart` per scenario: `medianDecisionMs`, `medianExecMs`, `medianAssertMs` | `summary[].jev` |
| Repeats | `ScatterChart`, x = scenario, y = totalMs, one point per measured repeat, shape by driver, failed = `--destructive` | `records` |
| Pass rate | horizontal `BarChart`, one bar per driver, label `n/N` | `summary` |

## Audit constraints — 2026-10-21

Dev has no benchmarks route/data loader yet. Use the corrected WM-3.1.1 schema:
show null/no-success latency as unavailable, never zero; validate the summary
against raw records, not just raw record shape. A missing-data state must work
without an unresolved static JSON import breaking compilation (use committed
empty fixtures or a supported optional loader). Weight pass rate by attempts,
not an average of scenario percentages. Label component medians as separate
statistics; their sum is not the median total. The overhead reference applies
to measured browser calls, not an assumed Playwright tool-step count of zero.
Align the summary table and tests on one row/column layout so driver toggles
and row-count assertions describe the same UI.
