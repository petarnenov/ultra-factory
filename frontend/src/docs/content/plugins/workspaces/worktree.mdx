---
title: Git worktrees
description: Isolated branches and files for sessions in Git projects.
---

Each Git-backed session gets its own worktree and branch, based on the project's configured `defaultBranch` rather than the branch currently checked out in your source repository. When the setting is `auto`, Orchestrator resolves the repository's Git default. Multi-repository workspaces resolve the root and each child repository independently.

```bash
ao project add --path /path/to/repo --worker-agent codex
ao spawn --project my-repo --name fix-auth
```

Worktrees keep checked-out files separate while sharing the repository's Git object database.

<span id="how-ao-chooses-the-base-branch" />
## How Orchestrator chooses the base branch

An explicit project `defaultBranch` selects the worktree base. Set it with `ao project set-config <id> --default-branch dev` when workers should start from `dev`. With `auto`, Orchestrator asks the selected remote for that repository's default branch. If it cannot reach the remote, Orchestrator uses that remote's cached `HEAD`.

For `ao spawn --host <host>`, the target host's daemon selects the base from its copy of the project's configuration. Configure the project on that host as well; the spawning machine's project setting is not sent with the request. In a multi-repository workspace, the explicit project setting applies to the root repository, while each child repository resolves its own configured or Git default.

Orchestrator records the base ref for each repository. Workspace and review diffs use it to recalculate the merge base after a rebase or when the repository default advances, so upstream-only changes do not appear as agent edits.

## Typed project settings

The daemon stores project configuration as validated JSON in SQLite. Relevant fields include:

| Field | Purpose |
| --- | --- |
| `defaultBranch` | Base branch for new session worktrees; `auto` resolves each repository's Git default. |
| `env` | Extra environment variables passed to agent runtimes. |
| `symlinks` | Repository-relative paths linked into each workspace. |
| `postCreate` | Commands run after workspace creation. |
| `agentRules`, `agentRulesFile` | Standing worker instructions. |

Use `ao project set-config <id> --help` for flags. To pass the complete object with `--config-json`, first read the [full-config warning](/configuration/projects#update-from-the-cli).

## Cleanup safety

`ao session kill` terminates the runtime, but preserves a worktree when cleanup cannot safely remove it. `ao session cleanup` reclaims eligible terminated workspaces and skips dirty ones; run with `--dry-run` first when you want to inspect the candidates.
